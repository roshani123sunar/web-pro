Accessibility Audit Report

Roshani Sunar | Student ID: 202537197 | Computer Engineering | Gachon University

Website: Web Programming Projects

1. Introduction

I checked my Web Programming Projects website using Google Chrome Lighthouse. The purpose of this audit was to find accessibility problems and improve the website so it is easier for people to navigate and use, including people who use a keyboard or assistive technology.

2. Before the Improvements

The first Lighthouse audit gave my website an accessibility score of 88/100. It reported a missing main landmark and a touch-target size or spacing issue.

3. After the Improvements

After updating my website and running Lighthouse again on the published GitHub Pages site, the accessibility score increased to 100/100.

4. Accessibility Improvements

1. Main landmark: I added a semantic <main> element around the main page content. This helps screen-reader users identify the central content.

2. Keyboard-friendly weekly sections: I used native <details> and <summary> elements for expandable weekly project lists. These support opening and closing sections with a keyboard.

3. Visible focus and larger links: I added :focus-visible outlines so keyboard users can see the selected item. I also set exercise links to a minimum height of 44 pixels to make them easier to select.

5. Conclusion

This audit taught me that a website should be easy to use as well as visually clear. I learned to use semantic HTML, support keyboard navigation, and make interactive links easier to select. My final Lighthouse accessibility score is 100/100. I will keep accessibility in mind when creating future web pages.
